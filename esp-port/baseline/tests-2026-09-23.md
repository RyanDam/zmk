## Failure cause (uniform across all 244 confirmed failures)

`app/src/indicator.c` — a file that exists **only on this branch** (absent in
`main`) — is compiled unconditionally (`app/CMakeLists.txt:116`, no Kconfig
guard). Its non-LED-strip `#else` path requires devicetree that the test
keymaps do not provide:

```
error: 'DT_N_ALIAS_led_l0_CHILD_IDX' undeclared here (not in a function);
       did you mean 'DT_N_S_leds_CHILD_IDX'?
```
(via `DT_NODE_CHILD_IDX(DT_ALIAS(led_l0))`, `indicator.c:47`)

and, where a `gpio_leds` node is also absent:

```
error: '__device_dts_ord___ORD' undeclared here (not in a function)
```
(via `DEVICE_DT_GET(LED_GPIO_NODE_ID)` with
`LED_GPIO_NODE_ID = DT_COMPAT_GET_ANY_STATUS_OKAY(gpio_leds)` = -1)

The `BUILD_ASSERT`s that document the LED requirement are commented out
(`indicator.c:35-40`).

## Data-quality note (concurrent-suite race)

An orphaned `./run-test.sh all` from a previous OpenCode session (started
13:40, parented to `opencode serve`) ran **concurrently** with this run in the
same `app/build/tests/` tree. Effects, all superseded by the per-test
`build.log` audit above:

- `pass-fail.log` (shared, truncated by each suite at start) lost 8 FAILED
  lines and contains 1 duplicate.
- The orphan was killed at ~14:40; the 4 interrupted targets above are its
  in-flight work.

Lesson recorded for Phase 4: run the suite in a dedicated build dir
(`ZMK_BUILD_DIR`) and never concurrently.

## Disposition

Fix as a **separate small PR** (Phase 0 records the red state, does not mask
it): guard the `#else` path of `indicator.c` on
`DT_NODE_EXISTS(DT_ALIAS(led_lN))` / `DT_NODE_EXISTS(LED_GPIO_NODE_ID)` (or
`-1` fallbacks + runtime checks). Re-run this suite after the fix and record
the result as the true green baseline before Phase 1 starts.
