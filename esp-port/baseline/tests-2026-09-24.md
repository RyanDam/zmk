## Fixes verified by this run (c01 + pre-existing branch bugs)

1. **c01 — `app/src/indicator.c`** (the item this baseline closes):
   - LED-strip path: `#error` when `CONFIG_COBAN_INDICATOR_USE_LED_STRIP=y`
     but the `zmk,indicator-strip` chosen node is absent (a
     `BUILD_ASSERT(DT_NODE_EXISTS(...))` would itself fail to compile when
     the node is missing).
   - GPIO path: `INDICATOR_LED_GPIO_PRESENT` / `INDICATOR_LED_GPIO_ACTIVE`
     guards; no-op `update_leds` (with `ARG_UNUSED`) when the `gpio_leds`
     node or `led-l0..l3` aliases are absent; the commented-out
     `BUILD_ASSERT`s restored, active only when the LED path is compiled in.
   - USB-conn listener wrapped in `#if IS_ENABLED(CONFIG_USB_DEVICE_STACK)`
     (the event is only implemented under that config; without the guard the
     test builds fail at link).
   - `get_color_rgb`/`hsv_to_rgb` wrapped in
     `#if IS_ENABLED(CONFIG_COBAN_INDICATOR_USE_LED_STRIP)` (avoids
     `-Wunused-function` in no-LED builds).
   - `cobanpad16a` firmware is byte-identical in size to the pre-fix
     baseline (see `build-sizes-2026-09-24.md`) — same code path on coban.
2. **`app/src/hid.c`** — restored the `LOG_DBG("Mouse movement set to
   %d/%d", …)` line the branch had commented out in
   `zmk_hid_mouse_movement_set`; the `pointing/mouse-move/*` snapshots
   depend on it (16 snapshot failures fixed).
3. **`app/src/keymap.c`** — the no-storage stub
   `zmk_keymap_set_layer_sensor_binding_at_idx` was missing the
   `uint8_t binding_idx` parameter present in the header and the
   storage-enabled variant (3 `encoders/*` build failures fixed).
4. **`app/src/behaviors/behavior_sensor_rotate_common.c`** — the branch's
   local-ID lookups (`zmk_behavior_get_local_id` /
   `zmk_behavior_find_behavior_name_from_local_id`) are only defined under
   `CONFIG_ZMK_BEHAVIOR_LOCAL_IDS` (selected by `CONFIG_ZMK_STUDIO`);
   wrapped in `#if IS_ENABLED(CONFIG_ZMK_BEHAVIOR_LOCAL_IDS)` with a
   `behavior_dev = "key_press"` fallback, which is exactly the value the
   local-ID round trip returns (3 `encoders/*` link failures fixed).
5. **`app/include/dt-bindings/zmk/pointing.h`** — reverted
   `ZMK_POINTING_DEFAULT_SCRL_VAL` 30 → 10 (upstream value). The 10→30
   change came from branch commit `9cf09687` ("Support mouse emulation
   param", whose actual purpose was Studio parameter metadata for
   `input_two_axis`). Neither coban keymap uses `SCRL_*` macros or
   `input_two_axis`, and the MPR121 touchpad emits movement directly via
   `zmk_hid_mouse_movement_set`, so the revert has no runtime effect on the
   coban boards; it restores the upstream scroll-speed expectation encoded
   in the `pointing/mouse-scroll/*` snapshots (5 snapshot failures fixed).
   If a faster default scroll was intentional for future scroll keys, that
   is a separate behavior decision to make explicitly.

## Test-infra note (pre-existing, not a code bug)

`parse_syscalls.py` walks `--include /workspaces/zmk/app`, which includes
`app/build/tests/*`. Stale per-test build dirs from a previous run get
wiped by a *concurrent* `west build -p` (board builds), producing
`FileNotFoundError` build failures in unrelated test targets. This bit 12
test targets and 2 board builds (`bdn9`, `cobanpad12b`) during the first
verification pass; all re-ran PASS in isolation. **Rule: never run board
builds concurrently with the suite.** This final run wiped
`app/build/tests` first and ran nothing else in parallel.

## A/B evidence for the scroll-speed revert

`pointing/mouse-scroll/*` passes on `main` (SCRL_VAL 10) and failed on the
branch (SCRL_VAL 30 → ~13 scroll reports/key instead of 4) before the
revert; all 5 pass after it.
